# open-session

**Routing and sequence only.** ⛔ **Every rule this session runs on lives in a file named below, and
where this file and one of those disagree, the file wins** — a skill is a view over its sources
(`AX-20`).

## Occasion
- A session opens over an instance, whether the operator names an intent or opens with nothing.
- A task reaches its close.

## 1 · Locate the instance

The operations centre is **a private sibling of this repository**. Read its `AGENTS.md` first: it is
**the binding** — which release it pins, where its ledger and its denylist live, and what colour
governs each file.

⛔ **With no operations centre attached, methodology is the whole of what is in scope.** Say so, and
stop there.

## 2 · Open

**The loop is `METHOD.md` §2** — the two ways in, the compass check before working, the plan sheet,
the closed destination vocabulary, and the capture that fires in the turn something is said. Run it
from there.

## 3 · Load only what the task needs

Read the routing index's row for this task and nothing else. ⚠️ **Anything opened beyond that row is
declared and logged as a defect in the index** (`AX-21`) — never as licence to read less.

| Doing what | Load |
|---|---|
| Executing a defined task | the binding · the role or skill file · `METHOD.md` §2 and §7 |
| Designing, auditing, or changing a rule | all three governance levels, both axiom departments |
| Anything in a project | that project's cartridge and its own axiom department too |

## 4 · Plan

**`skills/current-plan/` wins on everything about how a plan is written.** Invoke it when a
sub-block is reached; this file says only when.

## 5 · Close

**The order is `METHOD.md` §2's, and its steps are numbered there.** ⛔ **Step 3 stands before step
4: the audit reads the live plan, and only then does the plan close.** That ordering is the one a
close gets wrong silently — reversed, the auditor reads a file that no longer describes this round
while believing it read the reasoning.

⚠️ **Strike lines through rather than deleting them.** A struck line is a step the audit, and any
mid-task check, can see was taken. **A mid-task cadence exists when the operator names one for a
long task**, and no cadence is the default.

## What this skill does not do

It does not decide what to work on — the compass does. It holds no rules and points at all of them.
It does not commit on the operator's behalf, and it never empties a queue it filled (`AX-15`).
