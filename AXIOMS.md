# AXIOMS — the rules that may never be violated

> **Version:** unreleased · pre-release working draft. No tag exists yet, so nothing pins this;
> the first tagged release is stage 2's exit condition (AX-20).

> **Level 2 of three.** Above this file, `PHILOSOPHY.md` says what the company optimises for and
> breaks every tie. Below it, **decisions** are instance-level and live in the instance's own
> log, in a parseable format carrying author, date, reasoning and what was discarded. This file
> holds neither purpose nor record: **only the rules, and each one names the clause it serves.**
>
> **Who touches this file.** The superauditor checks these are not violated and never edits
> them. R&D proposes changes to them — this is the layer R&D works on when the work is improving
> the company. The operator decides. Nothing here may amend `PHILOSOPHY.md`.
>
> **Append-only from the first release**: entries are never rewritten; a later one supersedes an
> earlier one and says so. **Status:** 🟢 in force · 🟡 proposed · ⚫ superseded or retired.
> **Anchoring:** a bare `AX-n` inside this repo is unambiguous and stays bare; the moment it
> leaves it carries its anchor (AX-23), and an instance's or a project's own `AX-n` series is a
> different series resolved the same way.
>
> **How a rule gets here.** Not by being written down — by surviving a test:
>
> > **Would this still bind an instance that is not this one — a different person, a different
> > body of knowledge, different projects, a different toolchain?**
>
> **Twenty-nine axioms, distilled from 109 private decisions by that test.** The ratio is the
> point: a log where everything is a rule has no hierarchy, and a system that cannot tell its
> load-bearing rules from its housekeeping protects the wrong ones. What the test rejects is not
> lost — it stays private, which is where it was always true. Each axiom points at its origin as
> `NEXUS:M-nn`; those pointers resolve only for the operator, and the originals never move.
>
> **The set is kept honest in both directions by the promotion review** (`roles/superauditor.md`),
> which every twenty decisions asks what is missing, what is contradicted, and — the direction
> that stops inflation — **what is dead**: an axiom whose violation nobody would notice.

| **AX-1** | 🟢 | **Structure separates from state, and what is public carries no personal data.** The methodology — hierarchy, roles, skills, templates — is one artefact, public by release and depersonalised by construction. **Everything an operator actually works on — knowledge, projects, logs, decisions, work in flight — lives in NEXUS, the operations centre**: one private artefact per instance, a sibling of the structure, which the public one never contains. NEXUS is where the company lives and practically all work enters it; the structure only says how. **The direction of reference is one-way, and precisely bounded:** the structure names NEXUS's role and its conventional root — that is vocabulary — and names nothing inside it, no project, no person, no path below that root. NEXUS names the structure once, in its binding, and pins the release it runs. A boundary that depends on remembering to exclude something is not a boundary — the default is exclusion, so a forgotten thing fails private. | PH-5 · PH-3 | operator — `NEXUS:M-108` · `M-109` |
| **AX-2** | 🟢 | **Decision logs are append-only**, and therefore references name things rather than numbering them where a renumbering could not be corrected. **They are written in a parseable shape from the first entry, because they are the source of a generated database** — decisions, agent interventions, deliveries, the abbreviation dictionary, and the citations of AX-7 all become tables, queried rather than read: *has this been decided before?* and *what did we discard, and why?* stop being a re-read and become a query. Two consequences that cost nothing now and are unaffordable later: **the markdown stays the source and the database is a regenerated view** that is never hand-edited (AX-20), and **the field contract lives in the file's own header**, so format and parser cannot drift apart. Retro-fitting a shape onto eighty entries is the migration this avoids. | PH-3 · PH-4 | inherited — `NEXUS:M-87` · `M-93` |
| **AX-3** | 🟢 | **Every decision names who decided** — a person, `joint`, `inherited`, `agent`, or the method itself. `inherited` records how the constraint was discovered, because nobody here chose it, and it is the line between what can be renegotiated and what can only be found to be wrong. In this repo the person is written `operator` — names are instance data. | PH-4 | inherited — `NEXUS:M-100` |
| **AX-4** | 🟢 | **A rule only earns its place if it must fire while the work happens; if a cleanup pass over the finished artefact could apply it, it is a tool.** Rules are paid on every turn; tools are paid once. | PH-6 | inherited — `NEXUS:M-101` |
| **AX-5** | 🟢 | **The sharpened test for AX-4: does the information still exist at cleanup time?** A pass can fix what is in the artefact; it cannot recover what was only in the author's head. | **AX-6** | 🟢 | **A claim cites its evidence, or it is an opinion.** For a finding about the system: a file and line, or a command and its output. **For a claim about the world: a source, cited properly** — author, year, title, identifier, in a consistent style — and the citation is data, not decoration: it enters the generated database (AX-2) alongside the decision it supported, so *what is this built on* is a query. An assertion whose source cannot be named is marked as unsourced rather than quietly asserted; **that mark is a valid answer and hiding it is not.** And **any audit must be able to return nothing, saying what it checked** — silence with no account of what was checked is not available, because it is indistinguishable from not having looked. | PH-4 | inherited — `NEXUS:M-72` |
| **AX-7** | 🟢 | **A check carries the guarantee that it runs.** An invariant nobody verifies, and a tally nobody has tested, are opinions in the shape of facts — the tally that miscounts toward the convenient answer is the worst of them. | PH-4 | inherited — `NEXUS:M-90` |
| **AX-8** | 🟢 | **A conduct rule without a firing event loses to the stream of requests.** Every rule of conduct names the event that fires it; the counterweight is AX-4, or every rule gains an event and none is salient. | PH-6 | inherited — `NEXUS:M-96` |
| **AX-9** | 🟢 | **A task closes by enumerating every open thread with its destination — and *written* is read back from disk, never remembered.** The interval between decided and written is where work is lost. **A thread with no destination is a failure of the close, not an omission**, and the destinations are a closed vocabulary (`METHOD.md` §2) so the enumeration can be checked rather than admired. **This close is also the firing event for every reviewing role** (AX-8): they trigger on it, so an unclosed task silently disables the company's own detection — which makes the close the one step that may never be skipped for being obvious. | PH-3 | inherited — `NEXUS:M-105` |
| **AX-10** | 🟢 | **Split by owner first, rate of change second.** The owner decides which repo a thing lives in; the rate decides how it is sliced inside. This repo exists because the method layer's owner changed. | PH-5 | inherited — `NEXUS:M-46` |
| **AX-11** | 🟢 | **Every role is hired with its dismissal criterion fixed before it starts, countable by a command.** The first hire met its threshold on its first firing; the rule generalises the founding act, not a hope. | PH-6 | inherited — `NEXUS:M-106` |
| **AX-12** | 🟢 | **The governing document states what the system is for, and what it refuses, before it states any mechanism.** A charter that defines only mechanism gives no way to decide a case it did not foresee — and purpose is what breaks ties when two rules both apply. **The failure this prevents is measurable and was measured:** across one instance's most recent 39 rules, the conduct section was cited nine times and the purpose once. Salient rules crowd out founding ones, so the purpose is not a preamble — it is the last court, and it is written where it is read first. | PH-4 | inherited — `NEXUS:M-03` |
| **AX-13** | 🟢 | **Verification never shares a role with generation.** A single role holding both stances drifts toward the generative one, and a gate cannot be owned by the party producing the work. Three consequences: **one stance per conversation** — switching means a new conversation, not a new paragraph, because a second stance arriving with the first one's context loaded is the failure; **what can be decided by comparison is a script, not a role** — a role exists only to triage the script's report; and structural breaks belong to the script while semantic contradictions belong to whoever is already working. | PH-4 · PH-2 | inherited — `NEXUS:M-02` · `M-69` · `M-11` |
| **AX-14** | 🟢 | **Allocate work by what each access point is entitled to claim, not by what it can see.** Two independent axes fix the strongest available claim: *can it read the source* and *can it execute*. An access point given copies may claim only what it was given; one that reads the source may claim what is there; only one that can run things may claim that something passes. Two consequences: **what is handed to an executor is never the edit but the verification, stated as a prediction** — the executor returns the real output and the gap is the finding; and **the executor may refuse.** An executor that finds a task's premise false against what it actually sees stops and says so rather than executing. That is an obligation, not a discretion: whoever plans cannot see the state and whoever executes can, so the executor is the last point at which a divergence can be stopped. | PH-4 | inherited — `NEXUS:M-63` · `M-82` · `M-49` |
| **AX-15** | 🟢 | **The two channels are mirrors, and nobody empties the queue they fill.** An inbox runs from agent to operator; a task list runs from operator to agent; in each, the party that removes an item is never the party that added it. An access point working beside the operator writes to neither — it simply says the thing. **A queue that drains and a history that grows never share a file:** un-integrated deltas live in the inbox, completed interventions in an append-only log; the split is by lifecycle, not by scope. **The inbox is versioned and travels with its repository** — a local inbox on five machines is not one private inbox, it is five. **The one delegated deletion:** a task may name the entries it closes, and the executor deletes exactly those, because the decision to close them was made when the task was written. **And within a round the order is fixed:** integrate, write the decision down, *then* dispatch the next task — a decision left unwritten comes back as an open debate. | PH-3 | inherited — `NEXUS:M-65` · `M-05` · `M-15` · `M-58` · `M-48` · `M-07` · `M-76` · `M-35` |
| **AX-16** | 🟢 | **Completed work leaves the live list.** A finished task is deleted, not marked done — a list that only grows stops saying what is left — and its trace becomes a line in a dated, append-only log. **Every line of that log cites an artefact**, or it is not written: checkable detail, not more detail. **Every task carries its why**, not only its what, because an executor that does not know the purpose cannot exercise AX-14's refusal. **And the state record carries a freshness marker** naming how far integration has reached: version history says when a file changed, never how far the inbox was drained. | PH-6 | inherited — `NEXUS:M-42` · `M-99` · `M-88` · `M-06` |
| **AX-17** | 🟢 | **Three destinations by commitment, not by topic — and everything routes at the moment it is written.** Decided → the decision log. Undecided → an ideas register, one line while fresh, expanded only if it survives a second reading. **Committed but not started → a sequenced plan** with blocks, dependencies and a fallback — the drawer whose absence sends work into the wrong two. ⚠️ **A unit of work with no sequenced plan gets no third drawer either:** an unordered list of pending items is the backlog returning under a new name. **The registers split by tense** — state is the present, the plan is the future, the task list the imperative, the inbox what arrived — and a decision that changes the plan updates the plan in the same act, or the log stays current while the plan rots. **An item that resists routing is evidence the structure is wrong**, never that the item is special: redefine the structure rather than grant the exception. | PH-6 | inherited — `NEXUS:M-74` · `M-28` · `M-36` · `M-54` · `M-95` |
| **AX-18** | 🟢 | **The gate is set by the origin of the change; its shape by the channel.** What the operator originated is transcribed and logged without ceremony; **what the agent originated always goes through the gate** — and the notice is unconditional, never conditioned on the change seeming substantive, because that judgement is made by the interested party. Reversibility is never grounds to relax it: version control solves irreversibility, not divergence. **The shape follows the channel:** asynchronous through the inbox where the agent cannot reach the operator in the same turn, synchronous in session where it can — and because a synchronous gate loses the delay and the second reading, a change passing through one writes its log line in the same act. **What must be gated is a mechanical test**, not a feeling: it touches a protected file, it creates or retires an artefact, or it changes a written rule. **Two review surfaces, two scopes:** the diff is the gate for one change — applied, left uncommitted, read by the operator — and the branch is the gate for a session, which is what makes undoing ten files touched in one pass cheap. A bulk mechanical change lands as its own commit and starts from a clean tree, or the diff cannot separate the agent's side effects from the operator's edits. **At close, print what was touched** — one line per file, no pasted diffs. That table is not the review; it is the index that says where to look. | PH-4 · PH-2 | inherited — `NEXUS:M-34` · `M-59` · `M-64` · `M-50` · `M-61` · `M-92` · `M-60` |
| **AX-19** | 🟢 | **The permission model needs a class whose question is ownership, not risk.** Work the operator does not own is never modified — however dead it looks — and observations about it go to its owners' inbox instead. The other classes all describe things the operator or the agent owns, so none of them can catch this; the failure it prevents is an agent correctly evaluating an artefact's usefulness and never evaluating its ownership. Autonomy applies on one's own branch only, and the conduct that goes with the class **loads from a flag rather than sitting in the core rules** (AX-4). | PH-5 · PH-3 | inherited — `NEXUS:M-103` |
| **AX-20** | 🟢 | **A copy is either a generated view or a declared photograph — there is no third kind.** A **view** is regenerated from its source, cannot diverge, and loses on conflict; where a consumer can reach the source it reads it and keeps no copy. A **photograph** diverges on purpose and nobody updates it, so it is legitimate only when it carries three things: the date it was frozen, why, and **which copy wins**. Anything that is neither is a duplicate, and duplicates are debt with an expiry date or they are defects. **Generated output is byte-identical for identical input** — no run-time timestamps — so drift is detected by comparing content and history carries no empty diffs. **And every artefact stamps the version of the rule set it was written against:** without that line there is no way to tell a current document from one nobody has reviewed, and drift stays invisible at zero maintenance cost. | PH-5 · PH-3 | inherited — `NEXUS:M-66` · `M-97` · `M-33` · `M-47` |
| **AX-21** | 🟢 | **Startup reads state; knowledge loads on demand; anything opened beyond the index's row is a defect in the index.** At session start an agent reads where the work stands, what was decided and what is pending, from a literal path — never the body of knowledge, which is read when the reasoning touches it. **A routing index says not only what exists but when to read it**, and there is exactly one such map. **An agent declares every file it had to open outside the row it was pointed to** — and that gap is logged as a repair to the index, never as licence to read less: economy is bought by routing better, never by tracing less. **Rules travel, maps point:** whatever must survive a fresh checkout of one repository alone is generated *into* that repository; whatever would go stale if copied is a pointer. **And the agent contract of each repository is generated, never hand-written** — the method half authored once, the repository-specific half beside its repository, concatenated by a script into a file nobody edits, with a check that fails on drift. No repository is exempt, including the one that authors the method half. | PH-6 | inherited — `NEXUS:M-79` · `M-52` · `M-67` · `M-53` · `M-73` |
| **AX-22** | 🟢 | **Evidence comes before the argument, and before the deletion.** A decision resting on a checkable claim runs the command that would falsify it **before** anything is built on top; *"this rests on no checkable claim"* is a valid answer. Calibrate on the premise that feels obvious — that is the one nobody instruments. **Measure only freshly fetched data, and name which copy you measured**, or the check launders a stale reading into a measured claim. **Deleting anything requires the search that found no consumer, pasted with its output** — test coverage is not that proof, because coverage says what is tested, not what is used; if a change alters what any caller receives it is a redesign and needs a logged decision. **A session closes by running the checks and only then publishing, in that order** — and an agent that could not run them says so, because one that cannot verify and stays silent is indistinguishable from one whose checks passed. | PH-4 | inherited — `NEXUS:M-84` · `M-91` · `M-81` · `M-85` · `M-51` · `M-70` |
| **AX-23** | 🟢 | **Nothing is deleted; it is located — and a reference carries its scope the moment it leaves its own file.** Every deliberate exclusion — an ignore rule, a retired file, a detail summarised instead of kept — **names the address where the original still lives**. Deleting inside a version-controlled repository is not loss, because history is the raw layer; what loses data is an exclusion with no address. *"It is somewhere on disk"* is a claim with no check. **The mirror rule for references:** an identifier or a path stays bare inside the file that minted it and carries its repository anchor the moment it leaves — added at writing time, because the author can resolve the ambiguity then and no later sweep can (AX-5). | PH-3 | inherited — `NEXUS:M-80` · `M-89` · `M-102` |
| **AX-24** | 🟢 | **The log records what has no other record, and its fields can only be filled while deciding.** Version history already says what changed and when; the log says **why**, **who originated it**, and **what was discarded** — and the discarded option has no other trace anywhere, because it was never written. Never narrate the diff. **A discarded thing keeps its entry and its status**, adopted or rejected, or the same proposal returns in six months with nobody able to say it was already answered. **And every field of this kind is decision-time-only:** which sources informed a decision, who proposed it, what was rejected — these exist in the author's head at the moment of deciding and nowhere afterwards. A field that may legitimately be empty is written empty; a field left absent is indistinguishable from a real zero. | PH-3 | inherited — `NEXUS:M-41` · `M-55` · `M-77` |
| **AX-25** | 🟢 | **Passive detection: record what you cross, one line, and neither investigate nor fix it.** An agent that stumbles on an inconsistency while doing something else logs it and moves on. This is conduct carried by every working agent, not a role — and the firing event is precisely *while doing something else*, which is what keeps it free (AX-8). Going looking is an audit and belongs to whoever was hired for it; fixing it in passing turns one reviewable change into two. | PH-6 | inherited — `NEXUS:M-24` |
| **AX-26** | 🟢 | **A standard ships as a copyable template, and every line of an instruction file earns its place twice.** A standard that ships as a document to be read is met by intention; one that ships as a template with the files already written is met by default, and divergence becomes deliberate rather than accidental. **The two tests for any line in an agent instruction file:** *if the agent ignored this, would the output be wrong?* **and** *could it have worked this out by reading the repository?* Only yes-to-the-first, no-to-the-second stays. Everything else is methodology for the operator and belongs in the instance — an instruction file that bloats degrades weaker models, and the cost is paid on every turn (AX-4). | PH-1 · PH-6 | inherited — `NEXUS:M-22` · `M-44` · `M-25` |
| **AX-27** | 🟢 | **What is built once must be findable, and what will grow must name where it breaks.** Two halves of the same clause. **(a)** No artefact is reachable only through the conversation that produced it: anything worth keeping lands in a repository at a literal path, in the act that produces it — a result that exists only in a transcript was not built, it was mentioned. **(b)** Any artefact expected to grow **names the volume it was designed for and the first step that becomes manual beyond it.** A design that has not named its breaking point was not designed for scale; it was designed for today, and the difference only becomes visible when it is expensive. | PH-1 | superauditor round 3 — the clause the company calls its premise had no axiom implementing it |
| **AX-28** | 🟢 | **Automation is permitted for transcription and forbidden for judgement.** Copying, moving, formatting, generating a view: automate without asking. A choice between options, an acceptance of a trade, a decision about what matters: never. **Removing a decision from the operator requires a logged waiver naming what is given up** — and the waiver is what makes it reversible when the trade's review date arrives. **A change the operator cannot restate unaided does not ship**: a system its owner can no longer explain has already stopped being theirs, whatever the tests say. | PH-2 | superauditor round 3 — the clause marked ⏳ had nothing to revise |
| **AX-29** | 🟢 | **A document states its present. Its past belongs to the log, and both are written in the same act.** A live artefact — a rule, a prompt, a docstring, a comment, a definition — says what is true **now**. What it used to be, what was tried instead, why it is no longer done the old way: that is a decision's reasoning, and AX-24 already gives it a home. **The two halves are written together**, because a later pass can strip archaeology but cannot tell whether it was ever logged, and deleting unlogged history is the loss PH-3 forbids. Past tense survives in a live document in exactly one case: **naming a trap a reader can still fall into.** *"This used to be X"* is not that; *"do not do Y, it silently returns zero"* is. The cost of getting this wrong compounds — a document carrying its own changelog becomes unreadable at precisely the length where it matters most, and the reader who pays is the one who arrives latest and knows least. | PH-1 · PH-6 | operator — a recurring defect, measured across the founding rounds |

## Coverage — which clause each axiom serves

> **Regenerated from the Serves column, never hand-maintained** (AX-7). A coverage table typed
> from intent rather than read from the rows is a tally nobody tested.

Counted, not assumed (`PHILOSOPHY.md` § *How the levels are used*). A clause with few axioms is
not automatically wrong — but it is the place to look first, because **a priority nothing
implements is how a system ends up protecting what is merely salient.**
